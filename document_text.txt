    Master Project Definition Document / Project Charter / Technical Context

    1. Project Title & One-Sentence Summary
    
    Project Title
    MT5 AI Journal Analyzer
    
    
    One-Sentence Summary
    A secure, read-only, multi-broker SaaS platform that connects to MT5 Manager accounts, retrieves client/trade data and relevant journal/log events for selected time periods or trades, reconstructs what happened, calculates deterministic execution metrics, and optionally uses AI to explain the event in simple human-readable language.
    
    
    
    
    2. Background & Problem Statement
    MT5 brokers generate a large amount of operational information for every client action.
    A single client trade can generate multiple journal events.
    For example:
    2026.08.06 11:53:45.149Client 259713 sends BUY 0.01 XAUUSD.r at 4275.74↓Request transferred to dealer↓Dealer receives request↓Dealer confirms BUY 0.01 XAUUSD.r at 4275.75↓Deal performed
    A close operation can generate another sequence of events.
    For an active trader with hundreds or thousands of transactions, the resulting journal can contain an enormous number of log entries.
    Manually investigating this information is difficult.
    A broker employee may need to determine:
    What exactly happened?
    When did the client send the request?
    When did the dealer receive it?
    When was it confirmed?
    At what price was it executed?
    Was there slippage?
    How long did execution take?
    Was the request routed to a dealer?
    Which order/deal/position does the event belong to?
    Was the trade opened or closed?
    Was there an unusual delay?
    Was the issue caused by the client, broker, dealer, liquidity provider, or server?
    What should be communicated to the client?
    The platform exists to answer these questions automatically.
    
    
    
    3. Objectives & Success Criteria
    
    Primary Objectives
    
    Objective 1 — Secure Broker Connection
    Allow a platform user to connect an MT5 broker using:
    Broker name
    MT5 Manager/Admin server
    Manager login
    Manager password
    The platform must securely test and maintain the connection.
    
    
    
    Objective 2 — Client Investigation
    Allow the user to enter an MT5 client Login/MT5 ID.
    Example:
    259713
    The system should retrieve relevant client information and make it possible to investigate the client’s trading activity.
    The Manager API reference uses UserGet(login) for retrieving client information.
    
    
    
    Objective 3 — Time-Based Data Retrieval
    The user should be able to select:
    Client:259713From:2026-08-06 00:00To:2026-08-06 23:59
    The system should retrieve only the relevant data.
    Do NOT retrieve an unnecessarily large amount of history.
    The documented Manager API integration supports client-specific deal retrieval using:
    manager.DealRequestByLogins(    [login],    start_timestamp,    end_timestamp)
    
    
    
    Objective 4 — Trade Explorer
    Display the client’s trades in a clean table.
    Users should be able to select a specific:
    Order ID
    Deal ID
    Position ID
    Trade
    Transaction
    
    
    
    Objective 5 — Journal/Event Investigation
    Once a trade is selected, retrieve the relevant journal/log events associated with that trade whenever the underlying MT5 API/SDK provides access to those events.
    The system must NOT assume that trade history and server journal logs are the same thing.
    The development team must verify the exact journal/log retrieval capability against the official MT5 Manager SDK documentation.
    
    
    
    Objective 6 — Event Reconstruction
    Convert raw MT5 data into a chronological event timeline.
    Example:
    11:53:45.149Client request11:53:45.149Request transferred to dealer11:53:45.150Dealer received request11:53:45.152Dealer confirmed order11:53:45.152Deal executed
    
    
    
    Objective 7 — Deterministic Analysis
    Calculate metrics programmatically.
    Never ask AI to perform core numerical calculations.
    Metrics may include:
    Request latency
    Dealer response time
    Execution latency
    Slippage
    Spread
    Trade duration
    Execution price
    Requested price
    Confirmed price
    Number of retries
    Number of dealer interactions
    Event sequence
    Profit/loss
    Commission
    Swap
    Fees
    
    
    
    Objective 8 — AI Explanation
    After deterministic processing, optionally send a structured investigation to an AI provider.
    The AI should explain:
    What happened?
    Why did it happen?
    Was anything unusual?
    What evidence supports the conclusion?
    How should this be explained to the client?

    7. Constraints & Dependencies
    
    MT5 Manager API
    The Manager API is a native Windows dependency.
    The supplied architecture requires:
    Windows x64+MT5APIManager64.dll+MT5Manager Python wrapper
    The connector should therefore be isolated as a Windows service.
    
    
    
    Python
    Use a supported 64-bit Python version:
    Python 3.10–3.13
    Do not use Python 3.14 unless the installed MT5Manager package explicitly supports it.
    
    
    
    Connection Performance
    Initial Manager connections may take several seconds.
    The supplied architecture reports approximately 9 seconds for establishing a new connection and significantly lower latency for reused connections.
    Therefore:
    Never create a new Manager connection for every request.
    Use connection pooling/session reuse.
    
    
    
    DLL Thread Safety
    The supplied integration guide states that the native MT5 DLL client is not thread-safe.
    Therefore:
    Manager API calls        ↓Serialized access        ↓threading.Lock / RLock
    Never allow concurrent unsynchronized calls on the same Manager API instance.
    
    
    
    Server Load
    Large history queries can create unnecessary server load.
    Therefore:
    Require time ranges.
    Prefer client-specific queries.
    Limit maximum query range.
    Paginate where possible.
    Cache repeated requests.
    Rate-limit expensive operations.

    9. Risks, Issues & Mitigations
    
    Risk 1 — MT5 Manager Connection Failure
    Cause:
    Incorrect credentials
    Wrong server
    Firewall
    IP restrictions
    Broker configuration
    Mitigation:
    Connection test
    Detailed LastError()
    Connection status
    Automatic reconnect
    Audit logs
    
    
    
    Risk 2 — Excessive Server Requests
    Cause:
    Large journal/history queries.
    Mitigation:
    Time-range restrictions
    Rate limiting
    Caching
    Client-specific queries
    Lazy loading
    Maximum result limits
    
    
    
    Risk 3 — AI Token Exhaustion
    This is one of the most important product risks.
    A highly active client can produce enormous amounts of journal data.
    DO NOT send all logs to AI.
    Instead:
    Raw Data   ↓Filter   ↓Normalize   ↓Correlate   ↓Summarize   ↓Metrics   ↓AI
    AI should only receive the relevant investigation context.
    
    
    
    Risk 4 — AI Hallucination
    AI may incorrectly infer the cause of an event.
    Mitigation:
    Provide structured evidence.
    Include timestamps.
    Include raw event references.
    Separate facts from inference.
    Require confidence.
    Never allow AI to modify source data.
    
    
    
    Risk 5 — DLL Crashes
    Cause:
    Concurrent calls to native Manager API.
    Mitigation:
    Serialize Manager API calls.
    One controlled session per connection.
    Connection health monitoring.
    Automatic recovery.
    
    
    
    Risk 6 — Credential Exposure
    Mitigation:
    Encrypt broker passwords.
    Never expose credentials to frontend.
    Never log passwords.
    Environment-based encryption key.
    Restrict connector access.
    
    
    
    Risk 7 — Journal API Limitation
    The Manager API may not provide arbitrary Administrator/Server journal text through the same methods used for deal history.
    Mitigation:
    Verify official SDK documentation.
    Build an abstract JournalProvider.
    Support alternative officially permitted sources if necessary.
    Never invent an API.

    I. Trade Reconstruction
    MT5 deals are flat transaction records.
    They must be transformed into logical investigations.
    Basic process:
    Deals ↓Filter administrative transactions ↓Group by PositionID ↓Identify ENTRY_IN ↓Identify ENTRY_OUT ↓Identify ENTRY_INOUT ↓Build logical trade
    Financial calculation:
    Net Profit =Profit+Storage+Commission+Fee
    This reconstruction approach is documented in the supplied MT5 integration guide.
    
    
    
    J. Journal Processing Architecture
    Do NOT send raw journal data directly to AI.
    Use:
    MT5 Journal / Events        ↓Raw Event Parser        ↓Normalized Event        ↓Event Correlation        ↓Trade Investigation        ↓Metrics Engine        ↓AI Context Builder        ↓AI

    M. AI Cost-Control Strategy
    This is extremely important.
    A client can generate thousands of journal events.
    Never:
    100,000 journal lines        ↓       AI
